## In short

Releasing a new card benefit took 3 hours of an engineer's time and direct production database access. I built the API layer and self-service workflow that turned it into a 6-minute step.

## The problem

Every release pulled an engineer off their work to watch it, and needed direct production DB access, where one mistyped SQL command was a nightmare to undo.

## What I built

1. **Go/DynamoDB CRUD APIs** over the system-of-record tables, replacing direct database access
2. **A Node.js self-service workflow** that promotes changes from staging to production
3. **A cross-account pipeline:** QA manifest → Lambda → production Go API

## The hard part

Entries depend on each other, so promoting one alone leaves production "written but wrong." The API upserts each linked set **atomically**: all of it lands or none does. Failed writes page the team through CloudWatch → Splunk.

## What I learned

Many downstream teams depended on this service, and several pushed back. I met with senior engineers across the org to understand their constraints, and went through 5 architecture iterations before landing the design that runs today.
