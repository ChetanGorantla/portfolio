## In short

I built a real-time retail attribution backend on Python and Cloud Run. It matches point-of-sale transactions to ad impressions within a 2-minute window, which automates ad-to-purchase attribution.

## The problem

In-person advertisements work: few people think to round up for the children's hospital until the cashier asks for a donation. But measuring how well those ads perform is a major challenge for retailers everywhere.

## What I built

- **Ingestion:** 3 REST APIs on Cloud Run for real-time speech, POS, and video data
- **Speech:** an OpenAI classifier that extracts upsell intent and product mentions
- **Video:** a YOLOv8/OpenCV pipeline with calibrated proximity scoring to verify cashier-customer interactions

These services connect to web-server data streamed by a lightweight Raspberry Pi that records audible cashier interactions.

## The hard part

Two inputs I couldn't take at face value. **Speech is untrusted input:** transcripts end up inside a prompt, so extraction had to resist prompt injection. **Being close isn't interacting:** proximity scoring had to be calibrated before it could verify a real cashier-customer interaction.

## What I learned

Splitting work between hardware and software is a memory-versus-compute tradeoff. The Raspberry Pi's memory limits led me to keep the hardware lightweight and move accuracy-critical inference to the backend. Next, I'd field-test it to see how cost scales in production.
