# chetan-prod

A personal portfolio. The repo is called `chetan-prod`, but the site no longer shows that name. The site has two
layers:

1. **The dashboard.** Built with Next.js App Router, its content comes from MDX files in `content/`. It is one short
   page: a hero, an Experience ledger grouped by org, and a Projects plate. Every row has the same anatomy (title,
   dates, one sentence, tools, one result), and each opens a short first-person project report. (The code and URLs
   still say "incident" from the original theme; visitors only see "Project report".)
2. **The engine room.** A procedural pixel-art clockwork scene behind the page, in bronze and verdigris. It is
   painted at build time by plain TypeScript in `scene/` and animated in the browser by
   `components/engine-room/`.

The content always comes first. The engine room is atmosphere, and it must never get in the way of reading or
clicking.

This file is written for coding agents. It explains how the pieces fit, where things live, and the traps that are easy
to fall into.

---

## Commands

| Command | What it does |
|---|---|
| `npm run dev` | Paints the scene if `scene/` changed, then runs `next dev` on port 3000 |
| `npm run build` | Paints the scene if needed, then runs `next build` (every page is static) |
| `npm run paint` | Paints only. Add `-- --force` to repaint even when nothing changed |
| `npm start` | Serves the production build |

- **Node 22.18 or newer is required.** The painter runs `.ts` files directly with Node's built-in type stripping, with
  no tsx or ts-node. On Vercel, set Node to 22.x or 24.x.
- **There is no test suite and no lint script.** To verify a change, run `npm run build` and look at the page in a
  browser. Check both desktop width and phone width (around 390px).

## Content model

All copy lives in `content/`, parsed by `lib/content.ts` with `gray-matter` and rendered with `next-mdx-remote/rsc`.

### `content/profile.mdx`

| Field | Used by |
|---|---|
| `name` | Status bar, hero heading, OG image |
| `tagline` | Line under the name; also the OG image's plate |
| `currently` | The hero's "Now" line (joined with " · ") |
| `overview[]` | `{ value, label }`: the hero's headline numbers |
| `orgs[]` | `{ name, logo?, mark?, note? }`. Experience rows are grouped by their `org`. A `logo` is a wordmark and replaces the name; without one, the org shows its name and note, with its `mark` (a symbol) above them. Both are `.svg` or `.png` under `public/media/logos/` (the viewBox or PNG header sets the aspect); trim transparent padding so they line up with the text. An org not listed shows its name only |
| `links` | `{ github, linkedin, email }`; any can be `null`. Used by the status bar, phone menu and footer |
| body | Hero paragraph |

### `content/services/<slug>.mdx`

Each file is one dashboard row and one incident report. The filename must equal `slug`, or the build throws.

```yaml
slug: forge-family-dollar        # must match the filename
title: Forge × Family Dollar     # required
org: Texas Convergent            # or null; experience rows are grouped by it (see `orgs` in profile.mdx)
role: Tech Lead                  # or null; "Role · Team" renders the part after " · " muted
dates: Fall 2026 – Present       # or null
group: experience                # required: experience | project
status: in-progress              # required: resolved | shipped | in-progress | winner | operational
featured: true                   # tints the row's org and enlarges its result
order: 1                         # order on the page and for "Next" in reports (default 99)
metric: { label, before, after } # the row's result: "before → after", or just "after" when before is null
outcome: null                    # one line shown only when metric is null
summary: One or two sentences    # required; row text and meta description
tags: [Python, GCP]              # rows show the first 4; the report shows them all
numbers: [{ value, label }]      # extra headline numbers in the report, beside the metric
links: { demo: url|null, repo: url|null }
media: null                      # or { type: images|video, src: [...], alt: [...] }; shown in the report only
```

- **Groups become sections, in order.** `experience` is "Experience" and `project` is "Projects" (see `GROUPS` in
  `lib/content.ts`). In-progress and operational roles get a "Current" tag (on the page and in the report); no other
  status is shown anywhere, so visitors never see the old "resolved"/"shipped" wording.
  A winner's result is amber.
- **Media.** Local `src` paths are under `public/`. Files that are missing don't break the build; a placeholder keeps
  the layout. Remote embeds (YouTube/Loom) load only inside the report. Paths are case-sensitive on Vercel.
- **Report body.** Five short `## ` sections: `## In short` (the lead, full width), then `## The problem`,
  `## What I built`, `## The hard part` and `## What I learned`, which fill a two-column grid. The layout goes by
  position, so a title can vary ("What we built", "What I learned (so far)"); one starting "What I learned" gets the
  highlighted box. Keep each section to a few sentences or 3 bullets, so a report fits about one screen. Prefer bold
  lead-ins and lists. Don't use `>` blockquotes.
- **Write optional fields as explicit `null`.** Don't delete the key. A `null` on a required field such as `summary`
  fails the build.
- **`TODO (Chetan)` comments mark text only the owner can write.** Leave them in place, and never invent facts,
  numbers or titles to fill them.

## Routing and the drawer

- `/` is the dashboard. A report lives at `/<group>/<slug>` (`/experience/capital-one`, `/project/ontology`); build
  links with `reportHref(service)` from `lib/content.ts` and `<Link scroll={false}>`.
- **From the dashboard**, `app/@modal/(.)experience/[slug]` (or `(.)project/`) intercepts the link and renders
  `<Drawer>`, a native modal `<dialog>`. A direct visit or a reload renders `app/experience/[slug]` (or `project/`) as a
  full page instead. All four route files are thin: the shared code is in `components/report-routes.tsx`. Each uses
  `generateStaticParams` with `dynamicParams = false`, so a slug under the wrong group 404s.
- **Adding a group** means two new route folders (page and `@modal` drawer) and adding it to `REPORT_LINK` and
  `REPORT_PATH` in `drawer.tsx`.
- **Old `/incidents/<slug>` links** (shared before the rename) permanently redirect to the new address.
- **`app/default.tsx` must exist.** Next 16 needs it for the children slot. Without it, the page behind the drawer
  goes blank after some soft navigations.
- **The drawer manages its own scroll lock.** It locks `html` overflow when it opens and releases the lock on close,
  not on unmount. On close it calls `router.back()`. If the URL is still a report address with no open dialog, it
  falls back to a hard `location.replace("/")`.
- **`IncidentClickGuard`** (in `drawer.tsx`, mounted in the layout) ignores double-clicks and repeat clicks on report
  links outside the drawer. Stacked history entries for the same report used to strand the page.

## Styling

Tailwind 4 with the CSS-first config. Tokens and shared classes live in `app/globals.css`.

- **Tokens.** `--bg` is the dark room (#191814) and `--surface` is the ivory plate face. Text on plates uses `--ink`
  and `--ink-muted`; text set straight on the dark scene uses `--on-dark`. `--accent` is the verdigris used for links
  and focus. The status colors are `--ok`, `--info` and `--warn`. All are exposed as Tailwind colors (`text-ink`,
  `bg-surface`, ...).
- **`--art`** is one art pixel in CSS px: 2px, adjusted at 1.25 and 1.75 dppx so it stays a whole number of device
  pixels. Use `calc(var(--art) * n)` for anything that must line up with the pixel art.
- **Fonts.** Everything you read on a plate is Inter, numbers included (keep it that way: mixed faces made the old
  cards hard to scan). Silkscreen (`font-pixel`) is **only for the dark chrome**: the section tags (`.label-tag`).
  JetBrains Mono survives only in small chrome (the 404 line, the drawer's Esc key) and
  inline `code`.
- **Component classes:**
  - `.shell`: the 1100px content column
  - `.plate`: bronze instrument-plate frame (9-slice `border-image` from `/scene/plate.png`) with an ivory face. It
    sets `image-rendering: pixelated`, which is inherited, so photos and logos on a plate need `[image-rendering:auto]`
  - `.plate-link`: polishes the plate on hover
  - `.sunken`: recessed panel inside a plate
  - `.kicker`: small uppercase Inter label for use on plates (dates, report section heads, status)
  - `.label`: Silkscreen, uppercase; used with `.label-tag`
  - `.label-tag`: a label with a dark backing so it reads over the machinery
  - `.on-dark`: light text and a brass focus ring for text placed directly on the scene
  - `.lamp`, `.lamp-ok`, `.lamp-info`, `.lamp-warn`: the status lamps
- **Use static class names.** Tailwind only sees class names that appear literally in the source. Variable widths
  and spans therefore go through lookup maps (such as `FIGURE_COLS` in `incident-report.tsx`). Add to the map instead
  of building strings like `` `sm:grid-cols-${n}` ``.

### Pointer events: easy to break

`main` has `pointer-events: none`, so the background machinery behind the layout boxes stays clickable. Only
`main .plate`, `main .label-tag`, `main a` and `main button` turn pointer events back on.

**Any new interactive element inside `<main>` that isn't a link, a button or inside a `.plate` will not receive
clicks.** Give it `pointer-events: auto` or put it on a plate. When testing, use real mouse clicks; `element.click()`
skips hit-testing and will hide this bug.

## The engine room

### Build time: `scene/` → `public/scene/` + `lib/scene-manifest.json`

`scene/build.ts` paints everything with a seeded RNG, so builds are deterministic. It hashes the source of
`scene/*.ts` and skips painting when the hash matches the manifest. The output is gitignored; Vercel paints it during
`prebuild`.

| File | Role |
|---|---|
| `paint.ts` | `Bitmap` (RGBA buffer at art-pixel resolution), RNG/noise, Bayer dithering, lights, pixel text |
| `png.ts` | Dependency-free indexed PNG encoder (median cut when there are more than 256 colors) |
| `kit.ts` | Palettes (bronze, verdigris, iron, ivory, ...), `Relief` height-map bevel shading, plates, pipes, lamps, gauges |
| `gear.ts` | Gears split into a static part (painted into the layer) and a moving part (a frame strip covering one symmetry period) |
| `layout.ts` | **Where everything is**: `SCENE_W`, `LAYERS`, gear trains, lamps, gauges, flywheel, automaton stops, vents |
| `scene.ts` | Paints the far, mid and near layers (unlit, then lit) |
| `clutter.ts` | Filler machinery: pipe runs, tanks, cabinets, ladders, stencils |
| `sprites.ts` | Non-gear moving parts: crank, governor, pendulum/anchor, needles, lever, fire, indicators, automaton |
| `ui.ts` | Page assets: plate frame, ivory tile, lamp lenses, 404 labyrinth |
| `types.ts` | `SceneManifest`, the contract between the painter and the runtime |
| `build.ts` | Orchestrates painting: layers cut into 220px tiles at crops of 512/832/1280 (far: one 544 crop), sprite strips, lamp-off overlays, glows, automaton, UI pieces, `og.png` |

**Node type-stripping rules apply to everything in `scene/`.** No `enum`, no constructor parameter properties, no
`<T>value` assertions. Import with explicit `.ts` extensions and use `import type` for types. The runtime imports
`@/scene/types`, so keep that file type-only.

### Coordinates

- **Units.** Everything is in art pixels; 1 art px is about 2 CSS px.
- **Layers.** Each layer is `SCENE_W` = 1280 art px wide and centered on the page. The 1100 CSS px content column
  covers about x 365–915, so on wide screens the machinery shows in the margins beside it.
- **Mid layer zones,** top to bottom:
  - upper works: fine clockwork, and the flywheel (mostly behind the hero plate now)
  - middle works: pipes, valves, gauges
  - heavy works: boiler, big gear trains, furnace
- **Far layer.** Visible only through the mid layer's `OPENING`.
- **Scroll rates.** The layers scroll at 10%, 20% and 35% of the page (`LAYERS[*].rate`). The runtime scales them down
  on long pages so the art never runs out.

### Runtime: `components/engine-room/engine-room.tsx`

A single client component mounted behind everything in `app/layout.tsx`. It reads the manifest.

- **Loading.** It picks the narrowest crop that covers the viewport and lazy-loads tiles and sprites with an
  `IntersectionObserver` rooted on the room element.
- **The room holds still.** Nothing moves on its own: no gear loops, particles, lamp flicker or walking automaton,
  and hovering content doesn't wake anything. Each sprite shows its resting frame (`restFrame`: frame 0, the middle
  frame for a pendulum, `rest` for a gauge needle). The only movement is the **scroll parallax** (`place()`), which
  is kept on purpose. Don't add ambient animation back; it was removed for being distracting.
- **Darkness.** `.engine-veil` lays a dark gradient over the whole room (darkest behind the content column) so it
  stays in the background. It has `pointer-events: none`, so the easter eggs still work.
- **Easter eggs** move a part once, only when clicked. Invisible `.engine-egg` buttons (`tabIndex=-1`, decorative) sit
  over the steam-valve lever and the gauges (`playOnce`) and every lamp (switch off/on). The status lamp and the
  indicator strip run a health check (lamps sweep, the status lamp flashes); the header's status dot dispatches
  `HEALTH_EVENT` to do the same.
- **Reduced motion.** When the OS asks for it (`lib/machinery.ts`), there's no parallax and the eggs don't animate.
  There's no on/off switch in the UI. Mouse parallax exists but is off (`MOUSE_PARALLAX = false`).
- **Unused manifest data.** The painter still writes sprite frame strips, gear trains, vents, motes and the automaton.
  The runtime only needs frame strips for the resting frame and the two animated eggs; the automaton is used by the
  404 labyrinth.

**To change the art,** edit `scene/` (usually `layout.ts`), run `npm run paint` (or just restart `npm run dev`), then
reload. To add a new kind of manifest data, extend `scene/types.ts`, write it in `build.ts` and read it in the runtime.

## Gotchas

- **Service MDX edits don't show up in `next dev` until a restart.** `getServices()` caches at module level.
  `profile.mdx` and `oncall.mdx` are read fresh on every request. Production builds always read everything fresh.
- **Never commit `public/scene/` or `lib/scene-manifest.json`.** They are generated. If the build complains that the
  manifest is missing, run `npm run paint`.
- **File names are case-sensitive on Vercel.** A `src` that only matches with different casing works on Windows and
  404s in production. The headshot in use is `/media/headshot.JPG` (capital extension), set in
  `components/portrait.tsx` (`PHOTO` and `CROP`; the crop stops right of the raised hand).
- **`next/image` `priority` is deprecated in Next 16.** Use `loading="eager"` with `fetchPriority="high"` instead.
- **`app/opengraph-image.tsx` can't read CSS variables.** Its colors are duplicated in a `C` object; keep them in sync
  with `globals.css`.
- **Analytics** comes from `<Analytics />` (`@vercel/analytics/next`) in the layout. It also has to be enabled in the
  Vercel dashboard.

## Conventions

- **Keep changes surgical and match the surrounding style.** The code favors small components, short doc comments
  that explain *why*, and no extra abstractions.
- **Content changes go in `content/`, not in components.**
- **Accessibility is part of the design:**
  - status is never conveyed by color alone (a lamp plus a label)
  - focus rings are visible on both plates and the dark scene
  - reduced motion is honored everywhere
  - the engine room is `aria-hidden` decoration
- **Check the palette before adding colors.** New UI should use the existing tokens and plate classes. The look is
  bronze plates with ivory faces on a dark engine room, with verdigris accents.
